# Additional Requirements (Optional)

This folder covers the brief's **"Additional Requirements (Optional)"** section: the extras that go beyond the core task.

| Brief item | Done? | Where |
|---|---|---|
| **Documentation**: "a short document explaining your architecture decisions, how your system consumes and presents data, and things you would improve with more time" | ✅ Yes | [ARCHITECTURE.md](ARCHITECTURE.md) |
| **Accessibility**: "implement features to make your application more accessible" | ✅ Yes | Built into the app, and explained in [ACCESSIBILITY.md](ACCESSIBILITY.md) |
| **UI/UX wireframes**: "simple wireframes to show your design and user experience thought process" | ❌ No | Not chosen for this version (listed in [FUTURE_REQUIREMENTS.md](../FUTURE_REQUIREMENTS.md)) |

## What's in each document

- **[ARCHITECTURE.md](ARCHITECTURE.md)**: how the app is built and why.
  - A picture of how the parts fit together.
  - How we download Elanco's data and deal with lots of data, duplicates, broken records and Elanco's service failing.
  - How data is stored and served, and what happens when something goes wrong.
  - How the frontend works, how it's tested, and technical improvements for the future.
- **[ACCESSIBILITY.md](ACCESSIBILITY.md)**: everything we did so everyone can use the app, grouped by part of the app, with why each thing helps, how it was checked, and what's still missing.

The main requirements are in [../REQUIREMENTS.md](../REQUIREMENTS.md), and plans for later are in [../FUTURE_REQUIREMENTS.md](../FUTURE_REQUIREMENTS.md).
